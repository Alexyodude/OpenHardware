# Provenance

Where every file here came from, and why this repository can be MIT when the
project it drives is GPL-2-or-later.

Written 2026-08-23, when OpenHardware was extracted from a GitHub fork of
[`lcgamboa/picsimlab`](https://github.com/lcgamboa/picsimlab) into a
standalone repository. `rules/licence-hygiene.md` is the enforcement;
this document is the reasoning behind it.

**This is an engineering audit, not legal advice.** It records what was
checked and what was found, so that anyone who needs a lawyer's answer has the
facts to hand them.

---

## The short version

| tree | licence | why |
|---|---|---|
| `webui/`, `tools/`, `tests/`, `docs/`, `rules/`, `skills/` | **MIT** | written here; talks to PICSimLab over a socket, never links it |
| `patches/` | **GPL-2-or-later** | diffs against PICSimLab's GPL source |
| `webui/static/vendor/` | **MIT** © three.js authors | vendored dependency, unmodified |
| `tests/fixtures/sst8088/` | **MIT** © Daniel Balsom | excerpt of SingleStepTests/8088 |

PICSimLab itself is **not distributed with this software**. It is located at
runtime, from wherever the user installed it.

## 1. Why the web UI is not a derivative work

This is the load-bearing claim, so here is the evidence rather than the
conclusion.

### It talks over a socket

`webui/rcontrol.py` is a client for the TCP protocol implemented in
PICSimLab's `src/lib/rcontrol.cc`, default port 5000. Connect, send a
line, read a reply framed by `\r\n>`. That is the entire coupling.

- No PICSimLab source is compiled into anything here.
- No PICSimLab header is included.
- No PICSimLab library is linked, statically or dynamically.
- The two run as **separate processes** and would run on separate machines.

Arm's-length IPC between separate programs is the standard case for "not a
derivative work". A client is not a derivative of the server it speaks to.

### It reads artwork it does not ship

`webui/assets.py` reads `share/boards/<name>/board.svg` and `board.map` from
whatever PICSimLab install the user already has. Those files are upstream's,
GPL-2-or-later, and **this repository contains none of them** — check
`git ls-files share` and you get nothing.

Reading a file on the user's own disk is not redistribution. If OpenHardware
ever ships board artwork, that changes and this section must be rewritten.

### The tools read upstream source but are not built from it

`tools/draft_part_schemas.py` parses `sprintf` calls out of upstream's
`src/parts/*.cc` to draft schemas. `tools/check_board_contract.py` parses
`src/lib/board.h`. `tools/check_layering.py` scans `src/sim_backend/`.

A tool that reads a file is not derived from that file, any more than a
compiler is derived from the program it compiles. What those tools *emit* is
covered in §2.

## 2. The grey areas, stated plainly

Two categories are defensible rather than obvious. Both are documented in the
files themselves, which is why the audit could be done at all.

### 2a. Part schemas — `webui/parts/schemas/*.json` (12 files)

Each schema carries its own citation:

```json
"source": "src/parts/output_LEDs.cc:220",
"verified": "2026-08-12 arity, storage and settings-survival round-tripped ..."
```

The content is the **field order and labels of a positional config string** —
`L1`…`L8`, `active`, `color1`…`color8`, `Size` — read out of upstream's
`sprintf` argument order, because that is the only place the format exists.
`src/lib/part.h` offers name-to-id lookup and nothing else.

**Position:** this is interoperability information about a data format, not
creative expression. Field order in a config string is functional — it is what
you must know to talk to the program at all, and there is exactly one correct
answer. Interface information of this kind is the strongest case there is for
non-infringing reimplementation.

**Risk:** low, and not zero. The labels are upstream's chosen identifiers. If
this ever needed to be airtight, the schemas could be regenerated by
round-tripping configs against a running simulator — observing behaviour
rather than reading source — which `verified` already partially does.

### 2b. Board pin map — `webui/boards/Arduino Uno.json`

The file states its own derivation:

> Pad centres extracted from board.svg: circle elements mapped through viewBox
> `0 0 27957 21193` → 402x304 with the root `translate(-42763,-28610)`. The
> 14.4px spacing is the 0.1in header pitch.

So the coordinates were **measured from upstream's GPL artwork**.

**Position:** what was extracted is the geometry of a real Arduino Uno R3
header — 0.1 inch pitch, groups of 10+8 and 8+6. Those are physical facts
about third-party hardware, not PICSimLab's creativity. Measurements of facts
are not copyrightable.

**Risk:** low. The coordinates are expressed in upstream's SVG coordinate
space, which is the only thread tying them to that file. `webui/pinmap.py`
notes that pad position is **cosmetic** — wiring is by pin number — so this
data could be re-derived from an Arduino mechanical drawing at any time
without changing behaviour.

## 3. What is unambiguously GPL, and stays GPL

`patches/0001-board-arch-x86.patch` adds `ARCH_X86` to the architecture enum
in `src/lib/board.h`. It is a diff against a GPL file and is therefore
GPL-2-or-later. `LICENSE` says so, `patches/README.md` says so, and
`tools/check_licenses.py` fails the build if anything in that directory claims
MIT.

This is not a loose end. It is the correct label.

## 4. Third-party code kept verbatim

### `webui/static/vendor/` — three.js 0.185.1

MIT, © 2010-2026 three.js authors. `webui/static/vendor/LICENSE` is their
licence text, unmodified. Vendored rather than fetched because
`webui.pkg.offline-guarantee` requires a page that loads no CDN; costs ~2.1 MB.

**Never given a header of ours.** Relabelling a dependency misstates its
origin, which is worse than the missing-header case the checker looks for.

### `tests/fixtures/sst8088/` — eleven test cases

MIT, © Daniel Balsom, excerpted from
[`SingleStepTests/8088`](https://github.com/SingleStepTests/8088) v2.0.1.
Captured from a physical AMD D8088 (8441DMA, 1982) in Maximum Mode via the
Arduino8088 interface — hardware ground truth, and the only non-software
oracle this project has.

The full corpus is ≈2 GB and is fetched, not vendored:
`tools/get_8088_tests.sh` puts it in the git-ignored `third_party/`. The
eleven committed cases exist so the reader has offline, deterministic tests.

## 5. What the relicense actually changed

Every file here was previously headed GPL-2-or-later, inherited from the fork.
On 2026-08-23, 57 files written by this project's authors were changed to
`SPDX-License-Identifier: MIT`.

That was ours to do: the copyright in those files is the authors' own, and §1
establishes they are not derivative of upstream.

**The old GPL choice was not a mistake, and its reasoning is worth keeping.**
`rules/gpl-hygiene.md` required GPL-2-**or-later** specifically so the
combined work could move to GPL-3, because Apache-2.0 is incompatible with
GPL-2-only. Under MIT that constraint disappears — MIT is compatible with
everything — so the rule was retired rather than weakened. See
`rules/licence-hygiene.md` §0.

### Attribution did not change

None of the following is required by licence any more. All of it stays:

- `LICENSE` names PICSimLab and its author.
- Every part schema cites the upstream file and line it was read from.
- `README.md`, `CLAUDE.md` and `docs/picsimlab-reference.md` link upstream.
- `webui/` modules name the upstream source they were written against.

Relicensing our own code is not a reason to stop crediting the project this
one exists to serve.

## 6. If you are auditing this yourself

```bash
# Nothing of upstream's is tracked here:
git ls-files | grep -E '^(src|share|lib|package|debian)/'   # expect nothing
pytest tests/rules/test_inventory.py -k no_upstream_source  # pins it

# Every file states its licence, and patches are not mislabelled:
python tools/check_licenses.py

# Every upstream change is a documented patch:
python tools/check_deltas.py
```

The claims in §1 are checkable by reading three files:
`webui/rcontrol.py` (the socket protocol), `webui/assets.py` (reads, does not
ship), and `webui/picsimlab.py` (locates, does not contain).
