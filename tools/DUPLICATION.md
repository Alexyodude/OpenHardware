# What this repository states in more than one place

Surveyed 2026-08-31 for OH-149, by four parallel sweeps: the root documents
(CLAUDE.md, README.md, PROVENANCE.md, rules/, docs/picsimlab-reference.md,
docs/tickets/README.md, docs/known-issues.md), the docs/ tree, the checker
inventory, and the code. Line numbers are as of that date; the *relationships*
are the durable part.

The rule this list serves: **a fact stated twice will disagree with itself.**
For each relationship below, exactly one copy is the source and everything
else derives — and where a check now watches the pairing, it is a row in
`tools/checkall.py` or `tools/check_facts.py`. **Not in those tables means
not watched.** This file is the backlog and the reasoning; the tables are
the coverage.

This repository already practices the discipline in places — see §5 for the
guards that existed before this survey. What the survey adds is the honest
list of where it does not.

`check_facts.py` is deliberately **not** declared in `rules/*.md`
frontmatter. The frontmatter registry is what
`test_checkers_are_wired_into_ci` holds to a `run:` line in the workflow, and
arming a mechanism there means editing CI — outside this ticket's claim. It
does not need to: `tests/rules/test_check_facts.py` asserts `run_facts() ==
[]`, so bare `pytest` fails in CI on any of these claims going false. The
runner's table guard only requires that every *armed* checker has a row, not
the converse, so the two lists stay consistent. Registering it as a rule
mechanism, with the CI line to match, is the natural follow-up.

Ordered / self-checking, in `tools/checkall.py`:

  memory and diffed against disk, immune to mtime games.
- the runner's own table: every armed SCRIPT-ENFORCED checker in the rules
  frontmatter must be a row, or the run fails before it starts.

## 6. Traps recorded for whoever extends the tables

- `tools/check_ticket_claims.py` prints "the diff was NOT checked" warnings
  to stderr and still exits 0 — deliberate (warn-never-fail, rule §6), but a
  runner must surface the output or a quiet pass and a real one look alike.
- `tools/import_3d_model.py --check` alone exits 2; it wants `--all`.
- Registration is not coverage: adding a document to `check_facts.py`'s
  table does nothing unless an extractor matches how that document writes
  the claim — every extractor must complain when its pattern finds nothing,
  and every new row gets broken on purpose before it is believed
  (`python tools/checkall.py --prove` prints how).
