Runnable now computed from core/ and build/lib/

      

        
A target is runnable when it has a directory under
          core/ with a CMakeLists.txt — the same test
          tools/build_core.py applies — and that core has been
          built. Both halves are read from disk on every request, so deleting
          build/lib/ shows up here rather than making a target quietly
          disappear.

      

      

      

        
TargetStatusDetail

        
      

      

        
Built is not the same as drivable, and the table says both.
          A core is runnable when it exists and has been compiled. It is
          drivable when this page can put it on screen — and this page is an
          i8086 session, so its registers, disassembly and sample programs are all
          8086. A second core being built does not change that, and offering it in
          the selector would show 8086 state under another architecture's name.

        
The Cortex-M0+ core covers the whole 16-bit Thumb map
          — formats 1–19, so loads, stores, branches, the stack and the high
          registers, not only arithmetic. It runs a real compiled blink on an
          emulated RP2040, and it matched rp2040js for 100,000 instructions of an
          Arduino image before both models reached a boot ROM neither ships.

        
Which boards that adds up to is the Boards table below,
          and it is computed rather than claimed. A chip in the survey tables
          further down has no core directory at all; they are research, not work
          in progress, and they are deliberately absent from the selector rather
          than listed and greyed — an option you can never pick is a promise the
          repository has not made.

          is not a guess — and grouped by core, because that is

          Three boards is not worth a core nothing can check.

      

    


    

      
Emulation targets docs/architectures.md

      

        
Every chip on the board list, what emulating it would take, and — the part
          that decides everything else — whether a trustworthy oracle exists to check
          the result against.

        
A core is only as good as the thing you check it against. The
          8086 core reached 2,797,000 hardware-captured cases at 100% because
          SingleStepTests had already captured them. For every chip below, that corpus
          does not exist.

        
And “SST-shaped” does not mean hardware-captured. Only the
          x86 family claims hardware generation — ARM7TDMI comes from NanoBoyAdvance,
          m68000 from MAME, sh4 from Reicast. Simulator-generated, like the corpus we
          would be making.

FamilyCoreVerdictEvidenceWhat is actually known

        
          
C0Cortex-M0+ · 48 MHz
            BUILD OURSHAL SOURCE
            Reference chip, on a ~£12 Nucleo-C031C6. It has no
              PLL — so the survey’s four boot spins (a G0 figure) are really
              three: HSIRDY, ACR.LATENCY, SWS == SW.

          
G0 · L0 · U0Cortex-M0+
            BUILD OURSHAL SOURCE
            Same core, same approach. G0 is where the original four-spin
              measurement came from.

          
F0Cortex-M0 (not M0+)
            DROPPEDCMSIS HEADERS
            No VTOR, no CONTROL.nPRIV. The vector
              table is pinned at zero, so a per-case HardFault handler cannot be relocated — which
              makes the whole fault-outcome design impossible.

        
      

      

        
Throughput is answered, and without hardware. Roughly
          250–350 cases/sec for a competent rig — a full corpus in 2–3 hours,
          not two days. The feared 10× spread is host tooling: pyOCD on the on-board ST-LINK
          manages 19/s, while OpenOCD dap-direct or a ~£12 Raspberry Pi Debug Probe reaches
          245–2,000/s. The board decision is really a probe decision.

        
And the reason to buy silicon changed: every free Armv6-M model fails to model
          faults at all. They are a good oracle for the defined instruction space and a
          null oracle for the fault space — which is where a conformance corpus
          earns its keep.
