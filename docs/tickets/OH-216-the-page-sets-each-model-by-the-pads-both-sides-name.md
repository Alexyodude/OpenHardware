Follow-ups from OH-215 and its review (2026-10-09). OH-215 fixed the page's quarter turn by comparing two stated outline orientations (the board file's pad map and the model's `extras.pcb`). Three things remain, all in how the page sets a model on a board.

1. A turn chosen from pads, not from shapes. The comparison cannot tell an exactly square board (the Qwiic Pocket is placed right only because both comparisons tie; a near-square board could flip) or a half turn. Have the composer write its header pads into the model's extras (e.g. `header_pads: [[x, z, w, h, name], ...]` in model millimetres, named by net or pad number as the board file names them) and have `placeModel` choose the turn that lands the board file's pads on them, refusing by name when none does. The Glyph Mini's 0.73 mm centring offset (the composer centres on 46 pads of J3, J4 and J5, the board file on its 23) belongs here too: centre on the pads both sides name. `extras.pcb`'s `long` and `short` now mean the x and z extents, not sorted sizes, and the comment at `tools/import_3d_model.py` ~1718 still says "long side, short side": correct it, since sorting them would break the six boards again.
2. XIAO underside pads carve topside metal. The XIAO SMD and RP2350-DIP board files include underside pads, all tagged `header-top`, so `carvePins` gives each the topside metal above it and recolours it as a pin (OH-215's review: C3-SMD 1557 stray triangles, C6-SMD 3186, C5-SMD 2930, RP2350-SMD 5083, nRF54l15-SMD 5450, RP2350-DIP 3134), and that metal becomes the wire's anchor. The side a pad is on has to be stated in the board file (the importer reads it from the footprint's layers) and honoured by `carvePins`.
3. Fetched XIAO meshes carve little or nothing (SAMD21 0 of 14 and 0 of 20; RP2040, S3 and nRF52840 DIPs 0 of 14): on the SAMD21 the castellation copper tops out at 1.22 mm under a stated 1.61 mm PCB, so the "above the PCB top" filter excludes it. The pads stay as invisible colliders, the documented fallback; decide whether the filter or the stated PCB thickness is wrong.

Done when the page chooses each model's turn and centre from pads both sides name, every pad carves only metal on its own side, and each fetched mesh's castellations carve or say why not, each held by a test over every board.

**Note 2026-10-09:** SLICE A (item 2), underside pads. FINDING: the footprint's layers cannot state a pad's side -- every land of a XIAO SMD footprint is F.Cu (it is the HOST's land pattern; castellations and underside test points both solder to the host's top), so 'the importer reads it from the footprint's layers' was not possible as written. What the footprint does state is the module's own F.Fab outline: a pin whose every land lies wholly inside it is covered by the module and can only meet its underside. That alone misses underside pads whose land reaches the outline (the nRF54L15 SMD's NFC1/NFC2, the nRF54LM20A DIP's NFC1/NFC2/SHPHLD/GND), so where Seeed publish the module's own .kicad_pcb (third_party/seeed-pcb: C3, C5, C6, RP2350, nRF54L15, MG24, nRF54LM20A) tools/import_board.py --module reads it: a land at the edge over B.Cu-only copper and no plated-through pad is underside; the module is placed by the quarter turn that answers most of the outline's underside pins with back-side copper, nearest (refused by name when none does, or when tied turns disagree). The side reaches the page as the pad's GROUP, 'underside' (UNDERSIDE in import_board.py and board3d.js), because the group is the field webui/pinmap.py and webui/api.py already carry -- a new 'side' field would need both, outside this ticket's claim -- and because the group was what was false (the retired importer's 'header-top' by the sign of y). 16 XIAO board files changed, 203 pads, group lines only (checked line by line: same line count, every changed line a group line); written once from the importer's statement, since no live tool regenerates these files' other groups (they carry the retired importer's header-top/header-bottom). NOT stated: the nRF52840 SMD's NFC1/NFC2 (an edge land, and Seeed publish no board file for the nRF52840), so those two stay topside pads. board3d.js: carvePins takes metal below the PCB for an underside pad and above it for any other, never across; an underside pad's marker stands under the board; describe().underside says per underside pad whether it carved metal or kept only its collider. MEASURED with the node harness, triangles carved off their pad's own side or off every header pad, before -> after: XIAO-ESP32-C3-SMD 1557 -> 0, C6-SMD 3186 -> 0, C5-SMD 2930 -> 0, RP2350-SMD 5083 -> 0, nRF54l15-SMD 5450 -> 0, RP2350-DIP 3134 -> 0; each underside pad now carves 2 to 10 triangles of the composed model's own underside copper. Fetched meshes: the topside metal underside pads took (RP2040-SMD 448, nRF52840-SMD 454, S3-SMD 74, MG24-SMD 3904, nRF54LM20A-SMD 9081) is now 0; those pads carve nothing under the board.
