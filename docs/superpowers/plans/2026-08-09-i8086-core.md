# Strategy — x86-16 core (slice 2)

**Date:** 2026-08-09
**Ledger:** `docs/features/i8086.md` (43 cells)
**Status:** derived, not started
**Derived by:** the `feature-strategy` skill

Slice 2 of the roadmap in
`docs/superpowers/specs/2026-08-09-openhardware-feature-strategy-design.md`.
Its purpose is as much architectural as functional: it is the **abstraction
test** for the `bsim_*` seam. AVR and PIC are the shapes that seam grew around;
an x86-16 core is different enough to expose any assumption baked into it while
the fork is still young.

## 1. Phase 0 — what the base already provides

Every finding below was read from the source, with the construct that proves it
named. A rating with no citation is a hypothesis, and this project has already
shipped one wrong rating derived from a directory listing.

**The backend contract is 42 pure virtuals**, declared in `src/lib/board.h`
(lines 119-445). That is the true cost of a new architecture — not merely an
emulator, but an emulator plus the whole contract.

**The work splits across two classes.** `src/sim_backend/bsim_ucsim.h` carries
**31 overrides** (the `M*` simulation surface and the `DBG*` debug accessors);
`src/boards/board_uCboard.h` carries **17** (`Draw`, the `Ev*` input handlers,
`GetInputId`/`GetOutputId`). A new architecture therefore needs both halves, and
`bsim_ucsim` — not `bsim_qemu` or `bsim_simavr` — is the template, being the
only backend that wraps a simple non-QEMU engine.

**Nothing existing gives us x86-16 for free.** `src/sim_backend/bsim_ucsim.cc`
advertises exactly `PID_C51`, `PID_STM8S103`, and `PID_Z80`. uCsim as vendored
here has no 8086 target, so the "don't rebuild what exists" check comes back
empty. This was verified by reading the backend, not by assuming from the uCsim
project's general capabilities.

**Adding the two new files requires no upstream edit.** `src/Makefile.Common`
gathers sources by glob — `$(wildcard sim_backend/bsim*.cc)` and
`$(wildcard boards/board*.cc)` — so `bsim_i8086.cc` and `board_x86.cc` are
compiled automatically. Board registration is likewise self-service: the
`board_init(name, function)` macro at `src/lib/board.h:769` calls
`board_register`, and each board invokes it on its own last line, as
`src/boards/board_Blue_Pill.cc` does.

There is also an `exp_*` glob and a `make exp` target
(`src/Makefile.Common:17-27`), which is the natural staging home for a board
that is not yet fit to appear in the default build.

**One upstream delta is unavoidable.** `ARCH_*` is a bare enum at
`src/lib/board.h:40`:

    enum { ARCH_P16, ARCH_P16E, ARCH_P18, ARCH_AVR8, ARCH_STM32, ARCH_STM8,
           ARCH_C51, ARCH_Z80, ARCH_UNKNOWN };

`MGetArchitecture()` must return one of these, so adding `ARCH_X86` means
editing a file that existed at `fork-point`. This must be logged in
`docs/upstream-deltas.md` per `.claude/rules/upstream-sync.md`, and it will be
the ledger's first entry. It is also a single enum member and an obvious
candidate to contribute upstream, which would retire the delta entirely.

Insert the new member **before `ARCH_UNKNOWN`** only after checking whether any
serialised artifact stores these values as integers; appending in the middle
renumbers `ARCH_UNKNOWN`. Cell `i8086.int.arch-enum` owns that check.

**The remote-control interface cannot drive ISA conformance.**
`src/lib/rcontrol.cc` exposes `all blist buclist clk dumpe dumpf dumpr exit help
info oscmeasures oscrdcfg oscshow oscwrcfg pins pinsl quit reset sim splist
spshow start stop sync version` — read commands only. **There is no
register-write command.** Since every SST8088 case begins by imposing an
arbitrary initial register and memory state, the conformance harness must
instantiate the core directly rather than talking to a running PICSimLab.

That is the better design anyway: it keeps a suite of hundreds of thousands of
cases independent of the board and GUI stack, and fast enough to run per commit.
Upstream's own `tests/Makefile` already builds C++ tests that link against the
libraries, so a direct harness follows existing practice. `rcontrol` remains the
right channel for the board-level cells (`i8086.dbg.*`), which is what those
cells are for.

## 2. Two decisions the ledger defers to this document

### 2.1 Target the 8088, not the 8086 — `i8086.dec0.target-8088`

> **SETTLED 2026-08-12.** The recommendation below stands, and its premise —
> that the corpus exists and is usable — is now checked rather than assumed.
> `SingleStepTests/8088` is live, MIT, unarchived, last pushed 2025-09-03, and
> **≈2 GB**, which is what makes it a fetch rather than a vendor
> (`bscripts/get_8088_tests.sh`). Three facts the paragraph below got wrong or
> omitted, all corrected in the ledger: the case counts are five tiers not
> three; `v2` holds **324 files, not 256**, because group opcodes split by
> modrm.reg extension; and `final` is a **delta**, so a naive comparison
> against it passes while checking almost nothing. `tools/sst8088.py` reads the
> format and `tests/rules/test_sst8088.py` pins it against eleven verbatim
> cases held offline.

`SingleStepTests/8088` is MIT-licensed, generated from a real AMD D8088 (1982)
in Maximum Mode, and provides 10,000 tests per opcode for standard instructions,
2,000 for string operations, and 1,000 for flag operations. Each case carries
initial and final register and memory state plus a **per-cycle bus trace**.

No comparable hardware-generated suite exists for the 8086. The two parts share
an instruction set, so every register- and memory-level result transfers exactly
— but the 8088's 8-bit external bus and 4-byte prefetch queue (against the
8086's 16-bit bus and 6-byte queue) mean **cycle counts and bus activity do
not**.

The recommendation is therefore to make the 8088 the verification target. It is
the only x86-16 part whose behaviour can be checked against silicon rather than
against a manual, and it is the part the IBM PC actually shipped. The ISA
remains 8086; only the timing model commits to the 8088.

If the 8086's timing is wanted later, it is a separate ledger with a different
oracle — and, absent hardware, a weaker one. Do not quietly validate an 8086
timing model against 8088 traces.

### 2.2 Vendor or write — `i8086.dec0.vendor-vs-write`

Writing an x86-16 core is a solved problem several times over, and
`.claude/rules/gpl-hygiene.md` permits MIT, BSD, GPL-2, GPL-3, and — because
upstream is v2-or-later — Apache-2.0. A vendored core must therefore be licence-
audited before adoption, not after.

This cell is deliberately unresolved. It is listed first because it changes the
shape of nearly every `i8086.ins.*` cell beneath it: vendoring converts them
from "implement" into "verify and adapt", which is a different and much smaller
job. Resolve it before scheduling slice 2c.

Note the trap: a vendored core will not implement `board.h`'s 42 virtuals, and
the adapter is a real cost that partly offsets the saving. Size that adapter
against `bsim_ucsim.cc` before deciding.

## 3. Fidelity tiers and the one promotion

Forty of the 43 cells are `F0`. Three are promoted to `F2`, and the promotion
reason is recorded here because the ledger only records the tier:

- `i8086.time.instruction-cycles`
- `i8086.time.prefetch-queue`
- `i8086.time.bus-activity`

Cycle accuracy is normally the tier to avoid claiming, because nothing can check
it. Here the oracle carries a per-cycle bus trace — ALE assertion, multiplexed
bus value, segment and memory status, data bus content, bus status, T-state, and
queue operations — so `F2` is **verifiable rather than aspirational**. That, and
only that, justifies the promotion.

It is still the last slice. An `F2` claim resting on an unbuilt harness is
exactly the kind of overclaim `.claude/rules/conformance-fixtures.md` exists to
stop.

## 4. Slice order

Topologically sorted; each ends in something demoable, because a slice with no
demo is a slice nobody can review.

**2a — skeleton.** `arch-enum`, `bsim-skeleton`, `board-skeleton`,
`registration`. Demo: the board appears in the board list and loads; the CPU
does nothing. This is the abstraction test's first real signal — if the seam
fights an x86-16 shape, it shows up here, before any instruction is written.

**2b — memory and decode.** `memory-1mb`, `segmentation`, `loader`, `modrm`,
`segment-override`, `displacement`, `immediate`. Demo: step a byte stream and
show correctly decoded operands. Segmentation lands early because every later
cell depends on 20-bit physical addressing being right.

**2c — core ISA.** `mov`, `arith-add`, `arith-sub`, `logic`, `stack`,
`control-flow`, `flag.arith`, `flag.logic`. Demo: the SST8088 harness green
across these opcodes, plus a small program running to completion. Blocked on
decision 2.2.

**2d — full ISA.** `shift-rotate`, `muldiv`, `string`, `rep-prefix`, `bcd`,
`io`, `misc`, `flag.undefined`. Demo: whole-suite pass rate reported per opcode.
`flag.undefined` sits here deliberately: the documented-undefined flag results
are only knowable from hardware, which is precisely what this oracle is.

**2e — interrupts.** `vector-table`, `software-int`, `divide-error`,
`single-step`, `hardware-lines`. Demo: divide-by-zero vectoring through INT 0,
and TF-driven single-step. Depends on 2c for stack and control flow.

**2f — debug surface.** `register-inspect`, `memory-dump`, `step-run-reset`,
`pin-surface`, `draw`. Demo: driving the board headless over rcontrol. This is
where the board-level cells finally use the channel that could not serve ISA
conformance.

**2g — timing.** The three `F2` cells. Demo: cycle-exact agreement with SST8088
bus traces. Last, and only meaningful once 2d is green.

## 5. Rules that bind this work

- `.claude/rules/upstream-sync.md` — everything is additive except
  `i8086.int.arch-enum`, which must be logged in `docs/upstream-deltas.md`.
- `.claude/rules/core-interface.md` — nothing under `src/sim_backend/` may
  include from `parts/` or the UI. The 8086 core drives pins; it must not learn
  what is attached to them.
- `.claude/rules/conformance-fixtures.md` — no cell reaches `done` without a
  passing fixture, and no cell leaves `planned` without an oracle.
- `.claude/rules/determinism.md` — no `rand()`, `time()`, or `clock()` in the
  new core. A CPU emulator that consults wall-clock time is not replayable, and
  the suite depends on replay.
- `.claude/rules/gpl-hygiene.md` — the licence header on every new file, and the
  audit that gates decision 2.2.

## 6. What this slice is not

- Not an IBM PC. No BIOS, no PC peripherals, no disk. A board that runs
  instructions and exposes pins.
- Not an 8086 timing model — see 2.1.
- Not the analog solver, which remains slice 3 and still carries the open
  question in spec §4.1 about whether `SpareParts` can take shared-node
  semantics without changing its per-pin scalar signatures.
